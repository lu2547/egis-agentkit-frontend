# 工作台一致性与会话文件修复计划

**目标**：完成用户列出的八项修正，确保上传、交付、变更和删除都遵循当前会话边界。

**实现边界**：复用 AgentScope 原生 service、事件、存储与工具；只修改 framework 扩展和 app 薄接口。前端继续 Vue3/TDesign、独立组件与主题文件。保持顶部回复摘要与默认折叠。

**文件语义**：`work/<session_id>` 是会话过程文件，`artifacts/<session_id>` 是会话交付文件；上传在当前会话中可立即查看和使用。文件变更和产物列表均按当前 session 查询。删除会话清理该会话专属文件和记录，不影响其他会话、公共技能和用户偏好。现存误存于 work 的交付文件需要可发现和交付，避免只靠提示词要求模型写对目录。

## 特别检查

- 上传完成但尚未发送消息时，文件已在当前会话列表出现。
- 从会话 A 快速切到 B 时，A 的迟到响应不能覆盖 B。
- 同名文件属于不同会话时，列表、预览和删除均按会话区分。
- 修改、删除和异常中止不能把残留旧文件当成本轮新产物。
- 图片等大工具结果通过 Kafka 后保持原始事件内容和顺序；内部异常不泄露凭据。
